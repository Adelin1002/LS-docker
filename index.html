01 · Cycle de vie

Démarrer, arrêter et recréer

Démarrer les services

Essentiel

Crée et démarre les services. `-d` exécute en arrière-plan.

docker compose up -d

Arrêter et supprimer le projet

Arrête les conteneurs et supprime les conteneurs et réseaux créés par Compose.

docker compose down

Redémarrer des services arrêtés

Démarre des conteneurs déjà créés, sans les recréer.

docker compose start

Arrêter sans supprimer

Arrête les conteneurs. Ils pourront être relancés avec `start`.

docker compose stop

Redémarrer les services

Redémarre les conteneurs sélectionnés ou tous les services.

docker compose restart

Forcer la recréation

Recrée les conteneurs même si Compose estime qu'ils n'ont pas changé.

docker compose up -d --force-recreate

Mettre à l'échelle un service

Lance trois réplicas du service `web`. Attention aux ports fixes publiés.

docker compose up -d --scale web=3

Supprimer aussi les volumes

Supprime les volumes déclarés et anonymes attachés. Risque de perte de données.

docker compose down -v
02 · Build & images

Construire et télécharger les images

Construire les images

Construit les images définies par les instructions `build` du fichier Compose.

docker compose build

Construire sans cache

Ignore le cache de construction des couches.

docker compose build --no-cache

Construire puis démarrer

Construit les images avant de lancer les services.

docker compose up -d --build

Télécharger les images

Récupère les images référencées dans le fichier Compose depuis leur registre.

docker compose pull

Envoyer les images

Publie les images configurées vers leur registre. Authentification requise si privé.

docker compose push
03 · Inspection

État, logs et ressources

État des services

Liste les conteneurs du projet et leur état.

docker compose ps

Suivre tous les logs

Affiche les journaux et continue de les suivre en temps réel.

docker compose logs -f

Logs d'un service

Affiche uniquement les journaux du service `backend`.

docker compose logs -f backend

Processus dans les services

Affiche les processus en cours dans les conteneurs.

docker compose top

Images utilisées

Liste les images utilisées par les conteneurs du projet.

docker compose images

Statistiques des conteneurs

Affiche CPU, mémoire et autres statistiques d'utilisation.

docker compose stats

Valider la configuration

Résout et affiche la configuration Compose finale.

docker compose config

Voir le port publié

Affiche le port hôte associé au port du service.

docker compose port web 80
04 · Exécution

Exécuter des commandes dans les services

Exécuter dans un conteneur actif

Lance une commande dans un conteneur déjà démarré.

docker compose exec backend sh

Créer un conteneur ponctuel

Lance une commande dans un nouveau conteneur basé sur le service.

docker compose run --rm backend sh

Supprimer les conteneurs arrêtés

Supprime les conteneurs de service arrêtés. `-f` évite la confirmation.

docker compose rm -f
05 · Stockage & réseau

Volumes et réseaux

Compose crée et gère automatiquement les volumes et réseaux déclarés dans le fichier YAML. Les commandes de gestion globale des volumes et réseaux sont généralement des commandes Docker CLI.

Lister les volumes
docker volume ls
Inspecter un volume
docker volume inspect NOM
Lister les réseaux
docker network ls
Inspecter un réseau
docker network inspect NOM
Attention aux données : `docker compose down -v` peut effacer les données stockées dans les volumes du projet, par exemple une base PostgreSQL. N'utilise cette option que si tu souhaites réellement supprimer ces données.
06 · Configuration

Options globales utiles

Option
Utilité
-f, --fileIndiquer un ou plusieurs fichiers Compose.
-p, --project-nameDéfinir le nom du projet Compose.
--env-fileCharger des variables depuis un fichier d'environnement.
--profileActiver un ou plusieurs profils de services.
--project-directoryDéfinir le répertoire de base du projet.
--progressChoisir le format de progression, selon la commande et la version : auto, tty, plain, json ou quiet.

Utiliser plusieurs fichiers

Les fichiers sont fusionnés dans l'ordre ; les suivants complètent ou remplacent les paramètres précédents.

docker compose -f compose.yml -f compose.override.yml up -d

Activer un profil

Démarre aussi les services appartenant au profil `debug`.

docker compose --profile debug up -d
07 · Application pratique

Exemples Django, PostgreSQL & Next.js

Remplace les noms de services par ceux qui existent dans ton propre fichier Compose.

Django / backend

Migrations, administration et shell

Backend
docker compose exec backend python manage.py migrate
docker compose exec backend python manage.py createsuperuser
docker compose exec backend python manage.py shell
docker compose exec backend sh

PostgreSQL / base de données

Connexion et inspection

Database
docker compose exec db psql -U postgres
docker compose logs -f db

Dans l'exemple, `db` est le nom du service et `postgres` le rôle SQL. Adapte-les à ton fichier YAML et à tes variables d'environnement.

Next.js / frontend

Journaux et terminal

Frontend
docker compose logs -f frontend
docker compose exec frontend sh

Exemple minimal de fichier compose.yaml

compose.yaml
services:
  web:
    image: nginx:latest
    ports:
      - "8080:80"

Enregistre ce fichier sous `compose.yaml`, puis lance `docker compose up -d`. Ouvre ensuite http://localhost:8080. Les versions récentes de Compose n'exigent généralement plus la clé supérieure `version`.

08 · Dépannage

Problèmes fréquents

Un conteneur ne démarre pas

Consulte ses logs avec `docker compose logs -f NOM_SERVICE`, puis vérifie les variables d'environnement, les ports, les dépendances et la configuration avec `docker compose config`.

Un port est déjà utilisé

Modifie le port côté hôte dans la section `ports` du fichier Compose, ou identifie le programme qui utilise déjà ce port. Exemple : `"8081:80"`.

Les changements du Dockerfile ne sont pas pris en compte

Reconstruis l'image avec `docker compose build NOM_SERVICE`, puis recrée le service avec `docker compose up -d --force-recreate NOM_SERVICE`.

La base de données semble avoir perdu ses données

Vérifie que le service utilise bien un volume persistant. Évite `docker compose down -v` si tu veux conserver les données.

La commande ne trouve pas le fichier Compose

Place-toi dans le bon dossier ou indique le fichier explicitement : `docker compose -f chemin/compose.yaml up -d`.

💡

Conseil de sécurité

Avant une commande destructive, vérifie le projet et les volumes concernés. En particulier, `down -v` supprime les volumes gérés par Compose et peut effacer une base de données. Pour les projets importants, configure des sauvegardes régulières.
